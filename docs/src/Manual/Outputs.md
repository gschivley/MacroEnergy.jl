# Outputs

MacroEnergy.jl generates several output files after solving an optimization case. These files contain detailed results about system operations, investments, and costs. This page describes the structure and content of each output file.

## Output File Types

All output files can be generated in multiple formats:
- **CSV** (`.csv`) - Human-readable comma-separated values
- **Compressed CSV** (`.csv.gz`) - Compressed CSV format
- **Parquet** (`.parquet`) - Column-based format optimized for large datasets

The format is determined by the file extension used when calling the write functions.

## Output Layout

Results can be written in two layouts:
- **Long format** (default) - One row per observation, optimal for storage and analysis
- **Wide format** - Time series spread across columns, easier for visualization

Configure the layout using the `OutputLayout` setting in your Macro settings JSON file. See the [Writing Results to Files](@ref) guide for details.

## Output Files

### capacity.csv

Contains capacity investment decisions for all assets in the system.

**Generated by:** [`write_capacity`](@ref)

**Columns:**
- `case_name`: Name of the case
- `period`: Planning period (for multi-period cases)
- `location`: Geographic location/node
- `resource_id`: Asset identifier
- `resource_type`: Asset type (e.g., `ThermalPower`, `VRE`, `Battery`)
- `commodity`: Commodity type (e.g., `Electricity`, `NaturalGas`)
- `variable`: Type of capacity result (`capacity`, `new_capacity`, `retired_capacity`)
- `value`: Capacity value in MW (or appropriate units)

**Notes:**
- Final capacity includes both existing and new capacity
- New capacity shows investments made in each period
- Retired capacity shows decommissioned existing capacity

### costs.csv and undiscounted_costs.csv

Contains cost breakdown for the entire system.

**Generated by:** [`write_costs`](@ref)

**Columns:**
- `case_name`: Name of the case
- `period`: Planning period
- `location`: Geographic location
- `resource_id`: Asset identifier (or "system" for system-wide costs)
- `resource_type`: Asset type
- `commodity`: Associated commodity
- `variable`: Cost category (see below)
- `value`: Cost in USD (or configured currency)

**Cost Categories:**
- `fixed_cost`: Fixed O&M costs for existing and new capacity
- `variable_cost`: Variable O&M costs based on generation/consumption
- `startup_cost`: Startup costs for thermal units
- `shutdown_cost`: Shutdown costs for thermal units
- `investment_cost`: Capital expenditure for new capacity
- `retirement_cost`: Costs for retiring existing capacity
- `total_cost`: Sum of all costs

**File Variants:**
- `costs.csv`: Net present value (discounted) of all costs
- `undiscounted_costs.csv`: Nominal costs without discounting

### flows.csv

Contains operational dispatch decisions for all edges (flows between nodes) in the system.

**Generated by:** [`write_flow`](@ref)

**Columns:**
- `case_name`: Name of the case
- `period`: Planning period
- `location`: Geographic location
- `node_in`: Source node
- `node_out`: Destination node
- `resource_id`: Asset identifier
- `component_id`: Edge component identifier
- `resource_type`: Asset type
- `component_type`: Edge type
- `commodity`: Commodity being transported
- `variable`: Always `flow`
- `year`: Year within planning period
- `time`: Time step index
- `value`: Flow value in MW (or appropriate units)

**Notes:**
- Each row represents the flow through one edge at one time step
- Positive values indicate flow in the direction from `node_in` to `node_out`
- Time step index corresponds to the system's time structure

### curtailment.csv

Contains curtailment (unused renewable generation potential) for variable renewable energy (VRE) assets.

**Generated by:** [`write_curtailment`](@ref)

**Columns:**
- `case_name`: Name of the case
- `period`: Planning period
- `location`: Geographic location
- `node_in`: Source node
- `node_out`: Destination node
- `resource_id`: VRE asset identifier
- `component_id`: Edge component identifier
- `resource_type`: Asset type (e.g., `VRE`, `Wind`, `Solar`)
- `component_type`: Edge type
- `commodity`: Commodity (typically `Electricity`)
- `variable`: Always `curtailment`
- `year`: Year within planning period
- `time`: Time step index
- `value`: Curtailment value in MW (or appropriate units)

**Notes:**
- Curtailment is calculated as: `availability[t] × capacity - flow[t]`
- Only includes edges with availability data (VRE assets)
- Hydro spillage is separate and NOT included in curtailment output
- Curtailment represents generation that could have occurred but was not dispatched
- Zero or positive values only (never negative)

**Calculation Details:**

Curtailment is an implicit variable in the optimization model, calculated post-solve for VRE assets. The model allows VRE assets to generate less than their available capacity at each time step, and the difference is the curtailment.

For example, if a wind farm has:
- Installed capacity: 100 MW
- Availability at time t: 0.6 (60% capacity factor)
- Actual generation at time t: 45 MW

Then curtailment at time t = (100 × 0.6) - 45 = 15 MW

### duals.csv

Contains dual values (shadow prices) for key constraints in the optimization model.

**Generated by:** [`write_duals`](@ref) or [`write_duals_benders`](@ref)

**Columns:**
- `case_name`: Name of the case
- `period`: Planning period
- `location`: Geographic location
- `commodity`: Commodity type
- `constraint_type`: Type of constraint (e.g., `BalanceConstraint`, `CO2CapConstraint`)
- `node_id`: Node identifier
- `year`: Year within planning period
- `time`: Time step index
- `value`: Dual value (marginal cost)

**Notes:**
- Balance constraint duals represent marginal prices for commodities
- CO2 cap constraint duals represent carbon prices
- Other constraint duals show the marginal value of relaxing that constraint
- Dual values are only available when using barrier/interior point solvers

### system_data.json

Contains a copy of the system configuration including all input file paths and settings.

**Generated by:** Automatically during output writing

**Content:**
- Input file paths
- System structure and parameters
- Useful for reproducibility and documentation

### settings.json

Contains all case and system settings used for the optimization run.

**Generated by:** [`write_settings`](@ref) or automatically with other outputs

**Content:**
- Solver settings
- Algorithm parameters (Monolithic, Myopic, or Benders)
- Time structure settings
- Output configuration
- Financial parameters

## Multi-Period Cases

For multi-period optimization cases, outputs are organized by period:

```
results_period_1/
  ├── capacity.csv
  ├── flows.csv
  ├── curtailment.csv
  ├── costs.csv
  └── ...
results_period_2/
  ├── capacity.csv
  ├── flows.csv
  ├── curtailment.csv
  ├── costs.csv
  └── ...
```

## Filtering and Customization

Most output functions support filtering by:
- **Commodity**: Specific commodity type(s)
- **Asset Type**: Specific asset type(s) with pattern matching

Pattern matching supports:
- **Parameter-free matching**: `"Wind"` matches `Wind{Electricity}`, `Wind{Hydrogen}`, etc.
- **Wildcard matching**: `"Wind*"` matches `Wind`, `WindOffshore`, etc.

See the [Writing Results to Files](@ref) guide for examples.
